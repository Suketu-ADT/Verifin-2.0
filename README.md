# VERIFIN

**"Interpretable Hallucination Detection for Financial LLMs"**

VERIFIN is an advanced web application designed for evidence-grounded verification of LLM-generated financial summaries and answers. Built as a sophisticated AI/ML prototype, it provides a professional, highly readable interface for identifying and analyzing AI hallucinations in the financial sector.

## 🚀 Overview

VERIFIN verifies whether statements generated by an LLM (from financial documents like Annual Reports, 10-Ks, or Earnings Reports) are actually supported by the source document. It breaks down the text into atomic factual claims, retrieves relevant evidence, and classifies each claim using a Natural Language Inference (NLI) model.

**The Verification Pipeline:**
LLM OUTPUT ➔ CLAIM DECOMPOSITION ➔ HYBRID EVIDENCE RETRIEVAL (dense + BM25) ➔ NLI CLASSIFICATION ➔ FIGURE GROUNDING, ENTITY AND PERIOD CHECKS ➔ VERDICT POLICY ➔ EXPLAINABLE OUTPUT

## ✨ Features

- **Document Processing**: Upload financial PDFs and documents, which are automatically chunked and stored for page-aware retrieval.
- **Evidence Retrieval**: Leverages vector embeddings to find relevant source evidence for each claim.
- **NLI Classification**: Classifies every claim as `SUPPORTED`, `CONTRADICTED`, or `UNVERIFIABLE`.
- **Risk Analysis**: Calculates overall verification scores, claim confidence, and flags high-risk hallucinations.
- **Explainable Interface**: A highly intuitive, modern frontend providing full visibility into the AI's decision-making process.

## 📊 Evaluation Results

> **Status:** the **test split (240 claims) was scored exactly once**, after the system, thresholds and defaults were frozen using the dev split only. The test results are in the first table below. Development-split numbers further down were used to find and fix errors, so they are slightly optimistic; the held-out test numbers are the ones to quote.

### Held-out test results (n = 240; 109 supported / 91 contradicted / 40 unverifiable)

| System | Accuracy [95% CI] | Macro-F1 [95% CI] | Supported F1 | Contradicted F1 | Unverifiable F1 |
|---|---|---|---|---|---|
| **VERIFIN (default)** | **94.6 [91.7, 97.5]** | **95.2 [92.3, 97.7]** | 94.3 | 93.6 | 97.5 |
| VERIFIN end-to-end (real claim extractor) | 93.8 [90.4, 96.7] | 94.2 [90.9, 97.0] | 93.8 | 92.6 | 96.3 |
| VERIFIN with larger NLI (deberta-v3-base) | 93.3 [90.0, 96.2] | 93.7 [90.3, 96.5] | 93.3 | 92.6 | 95.1 |
| VERIFIN, raw NLI output only (no deterministic checks) | 75.8 [70.0, 80.8] | 66.8 [59.2, 73.0] | 88.0 | 73.6 | 38.7 |
| `number_match` heuristic (no ML) | 81.7 [76.2, 86.7] | 79.7 [73.2, 85.1] | 86.9 | 77.3 | 75.0 |

- Test macro-F1 (95.2) is 1.5 points below dev (96.7), inside the confidence interval: the expected small drop after tuning on dev, with no sign of a large overfit.
- Differences between VERIFIN, the end-to-end variant and the larger NLI model are **not statistically significant** (McNemar p = 0.63 and 0.38). The deterministic layer is what matters: raw NLI alone scores 66.8 and VERIFIN 95.2 (p < 0.001).
- VERIFIN beats the number-matching heuristic by 15.5 macro-F1 (p < 0.001). The heuristic scores 0% on direction flips and unit swaps.
- Flagging view (claim flagged when not SUPPORTED): any-unsupported precision 93.4%, recall 97.7%, false-positive rate 8.3%; contradicted-only recall 96.7%.
- Confusion matrix (rows = truth): supported 100 / 8 / 1, contradicted 3 / 88 / 0, unverifiable 0 / 1 / 39 (columns: supported / contradicted / unverifiable).
- Page Recall@3 of retrieval 95.0%, MRR 0.885, ECE 0.183; mean 1.0 s per claim on CPU (1.6 s with the larger NLI model).
- Weakest areas on test: paraphrased supported claims (83.9%) and unit swaps (93.3%). All five unverifiable subtypes score 87.5-100%.
- The original pre-improvement system (v0) was not scored on test because its code no longer exists in that form; its dev-split numbers are shown below for the improvement history.
- The LLM-judge with retrieved evidence has not been scored on test yet (pending).

### Method

- **Corpus:** 6 public reports (JPMorgan 2025, Reliance 2025-26, SBI 2025-26, Tata Motors 2024-25 annual reports; HDFC Bank 32nd AGM transcript; Wipro 79th AGM notice), about 16,000 text chunks. Wipro yielded no usable sentences, so it has no evaluation claims.
- **Dataset:** 594 claims whose labels are correct by construction, not hand-labelled by a model.
  - `SUPPORTED` (282): a verbatim report sentence (195), or a Qwen 2.5 7B paraphrase accepted only if every number is preserved and no antonym of the original direction word is introduced (87).
  - `CONTRADICTED` (212): one controlled edit of a supported sentence: `number_change` (115), `unit_swap` (34), `period_swap` (32), `direction_flip` (31). A numeric edit is rejected if the new value appears anywhere in the report.
  - `UNVERIFIABLE` (100): plausible claims about invented entities (penalty, facility, bond, acquisition, appointment) whose names appear nowhere in the report.
  - **Split:** by hash of (document, page): dev 354 (173 / 121 / 60) and test 240 (109 / 91 / 40). Seed 1337; `python -m eval.build_dataset` rebuilds it.
- **Metrics:** accuracy and macro-F1 with 95% bootstrap confidence intervals, per-class F1, exact McNemar test against the reference system on the same claims, flagging precision/recall/false-positive rate, page-level Recall@k and MRR, expected calibration error (ECE), latency. CPU only; no GPU.

| truth \ predicted | SUPPORTED | CONTRADICTED | UNVERIFIABLE |
|---|---|---|---|

| CONTRADICTED (121) | 2 | 118 | 1 |

Flagging view (a claim is flagged when its verdict is not SUPPORTED, v4): any-unsupported precision 94.7%, recall 98.9%, false-positive rate 5.8%. Contradicted-only precision is 63.0% (recall 98.3%, false-positive rate 30.0%) because that view counts correctly flagged unverifiable claims as false alarms.

### Why the original system failed

The original verdicts were worse than a lexical baseline. Root causes found by error analysis:

1. The numerical reasoner compared a claim with arbitrary numbers in the evidence (footnotes, page numbers) and reported a mismatch: **80% of supported claims were falsely flagged** (false-positive rate 80.3%). It also could not parse Indian digit grouping (3,71,085), crore/lakh units, or the rupee sign (extracted as `H`, `I` or a backtick).
2. NLI ran on 500-character chunks and the "any contradiction wins" rule let one unrelated chunk veto a verdict.
3. There was no check for names that appear nowhere in the document (unverifiable class scored 0.0 F1).
4. The temporal check produced false positives and misses.

### Ablations (dev split)

| System | Accuracy | Macro-F1 [95% CI] |
|---|---|---|
| v0 original, numerical reasoner disabled (NLI only) | 54.2 | 49.1 [43.9, 54.1] |
| v1 with legacy NLI aggregation | 77.7 | 81.3 [77.3, 84.8] |
| v1 with aligned NLI aggregation (default) | 92.9 | 93.9 [91.3, 96.1] |
| v4 raw small-NLI output, before the verdict policy | 78.0 | 70.6 [64.6, 75.9] |
| v4 full pipeline | 96.3 | 96.7 [94.5, 98.3] |

The deterministic layer (figure grounding, entity novelty, period check, verdict policy) lifts raw NLI from 70.6 to 96.7 macro-F1. Most of the system's accuracy comes from that layer, not from the NLI model.

**Leave-one-out ablation of the v4 pipeline** (each row switches off one check; dev split, n = 354; p is McNemar against the full pipeline):

| Check switched off | Accuracy | Macro-F1 [95% CI] | Change | p |
|---|---|---|---|---|
| none (full pipeline) | 96.3 | 96.7 [94.5, 98.3] | - | - |
| Entity novelty (names absent from the document) | 85.3 | 76.4 [70.6, 81.5] | -20.3 | < 0.001 |
| Figure conflict (changed figure in the matching sentence) | 92.1 | 92.7 [89.8, 95.1] | -4.0 | < 0.001 |
| Grounded support (figures all found, NLI neutral) | 94.4 | 93.9 [91.2, 96.5] | -2.8 | 0.016 |
| Fiscal-year period check | 94.6 | 95.2 [93.0, 97.2] | -1.5 | 0.031 |
| Neighbour-chunk expansion | 95.8 | 95.6 [92.9, 97.6] | -1.1 | 0.625 (not significant) |
| Derived-value recomputation (growth %, margins) | 96.3 | 96.7 [94.5, 98.3] | 0.0 | 1.0 |

Entity novelty, figure conflict, grounded support and the period check each make a statistically significant difference. Derived-value recomputation and table arithmetic show **no effect on this dataset** because it contains no derived-percentage claims and no structured tables; they are covered by unit tests, not by this evaluation, and should not be credited with the measured accuracy. Neighbour expansion helps (about 1 point) but is not significant at this sample size.

### Cross-encoder reranker (dev split)

An optional reranker (`cross-encoder/ms-marco-MiniLM-L-6-v2`, top-15 candidates, `reranker_enabled` setting) was evaluated on the dev claims that have gold evidence (n = 294, k = 3):

| First stage | Page Recall@3 without → with | MRR without → with | Extra time per claim |
|---|---|---|---|
| BM25 | 99.0% → 100% | 0.981 → 0.993 | about 0.6 s |
| Hybrid (default) | 96.6% → 98.0% | 0.900 → 0.971 | about 0.5 s |
| Dense only | 88.8% → 96.9% | 0.803 → 0.961 | about 0.8 s |

Paraphrased claims benefit most (hybrid MRR 0.856 → 0.968). Through the full pipeline the final verdicts barely change: macro-F1 96.7 → 96.9, a one-claim difference that is not significant. **The reranker is therefore off by default** and available as an option; the existing verdict rules already recover from most retrieval misses.

### End-to-end with the real claim extractor (dev split)

Most results above pass each claim to the pipeline as-is. With the production claim extractor in front (a statement is as bad as its worst extracted claim), dev macro-F1 is **95.5** (accuracy 94.9%, CI 93.4-97.5), about 1.2 points lower, within the confidence interval. The extra errors come from trailing PDF fragments (footnote markers, page headers) that the extractor splits off as separate "claims"; this is largely an artifact of how the dataset's verbatim sentences were cut from PDFs. Two real extractor defects were found and fixed using this analysis: sentence splitting at abbreviations such as "N.A." and "Rs.", and sub-claims losing their subject or reporting period when a sentence was split at ", and".

### LLM-judge baseline without evidence (dev split)

Qwen 2.5 7B asked to judge a claim about a named company report without seeing the report scores **13.7 macro-F1** (accuracy 19.5%). It answers UNVERIFIABLE for 334 of 354 claims, because it cannot know the report's figures. This shows that an LLM alone cannot verify claims against a document; it is not a strong baseline. The comparison with evidence supplied is reported below when available.

### Retrieval comparison (original system, dev split)

| Mode | Page Recall@k | MRR | Final macro-F1 (v0) | Mean s/claim |
|---|---|---|---|---|
| BM25 only | 99.0 | 0.981 | 36.6 | 0.34 |
| Hybrid (dense + BM25, RRF), k = 3 (default) | 96.6 | 0.900 | 29.4 | 0.63 |
| Hybrid, k = 5 | 97.6 | 0.902 | 26.4 | 0.83 |
| Dense only | 88.8 | 0.803 | 29.0 | 0.53 |

On this dataset BM25 retrieves the gold page best (99.0% vs 96.6% for hybrid) because claims are built from report sentences and share exact words and numbers with them. Dense and hybrid retrieval are expected to matter more for paraphrased or reworded claims. This has not yet been separated by tier or re-run on the v4 pipeline, so the default is unchanged and the question is open.

### Calibration and speed

- ECE fell from 0.400 (v0) to 0.172 (v4), but the confidence of rule-derived verdicts is an evidence-alignment score, **not a calibrated probability**. Calibration is not yet solved.
- About 0.76 s per claim (p95 1.02 s) on a CPU, excluding claim extraction.

### Known limitations (read before quoting the numbers)

- **Dev split only.** Figures are tuned on the dev errors; expect lower numbers on test.
- **Unverifiable = invented names only.** The 100% score on that class comes from a rule that flags capitalised names absent from the document, which matches how those claims were generated. Real unverifiable claims (plausible facts the report simply does not state) are not covered.
- **Contradictions are programmatic edits**, mostly numeric. Subtle semantic contradictions are under-represented. `period_swap` labels are arguable when a report states both years.
- **Verbatim claims are easy** (95.7%); paraphrases are harder (91.1%).
- **Remaining 13 dev errors:** 3 supported verbatim claims wrongly contradicted by the NLI model, several caused by the right sentence not being retrieved (boilerplate repeated across years), and 2 claims about Tata interest expense whose evidence sentence is not retrieved.
- **Same-sentence figure swaps** (for example exchanging this year's and last year's values) are grounded as long as both values appear in one sentence; only NLI and direction checks can catch them.
- Labels are correct by construction but have **not been human-audited**; a 40-50 claim spot-check with inter-rater agreement is planned.
- No OCR (scanned pages are skipped). HDFC and Wipro are transcript/notice documents, not full annual reports.

### Reproduce

```bash
cd backend
python -m eval.build_dataset                                   # rebuild the dataset (needs Ollama + qwen2.5:7b)
python -m eval.run --split dev --systems verifin --run v4       # score a system
python -m eval.report --split dev --systems verifin --run v4    # tables + CI + McNemar
python -m pytest                                                # 164 unit tests
```

Raw per-claim predictions are in `data/eval/results/<run>/<split>/`.

## 💻 Getting Started

The frontend is built with Vite and uses modern React features.

cd frontend

npm install

# Start the development server

Rename `.env.example` to `.env` in the `frontend` directory and populate any necessary API endpoints or feature flags.

## 🎨 Design Philosophy

VERIFIN is designed to look like a modern AI fintech product:
- **Trustworthy & Professional**: Deep navy, neutral grays, and clean typography.
- **Clear Risk Indicators**: Green (Supported), Red (Contradicted), and Amber (Unverifiable).
- **Intuitive Visualizations**: Easy-to-understand charts and badges for technical ML data.
