==================================================
1. CORE PRODUCT IDEA
==================================================

VERIFIN verifies whether statements generated by an LLM from financial documents are actually supported by the source document.

The system must:

1. Accept a financial document such as:
   - Annual Report
   - 10-K
   - 10-Q
   - Earnings Report
   - Financial Statement
   - Investor Presentation
   - Financial PDF

2. Accept an LLM-generated:
   - Summary
   - Answer
   - Financial analysis
   - Set of statements/claims

3. Decompose the generated output into atomic factual claims.

4. Retrieve the most relevant evidence from the uploaded financial document for every claim.

5. Use an NLI model to classify every claim as:
   - SUPPORTED
   - CONTRADICTED
   - UNVERIFIABLE

6. Calculate:
   - Claim confidence
   - Evidence similarity
   - Overall verification score
   - Hallucination risk
   - High-risk claim count

7. Optionally inspect attention patterns as an auxiliary diagnostic signal.

8. Show the result in an extremely understandable visual interface.

The main principle is:

LLM OUTPUT
      ↓
CLAIM DECOMPOSITION
      ↓
EVIDENCE RETRIEVAL
      ↓
NLI CLASSIFICATION
      ↓
SUPPORTED / CONTRADICTED / UNVERIFIABLE
      ↓
RISK ANALYSIS
      ↓
EXPLAINABLE VERIFIED OUTPUT

- Text chunking
- Page-aware document storage

RETRIEVAL:
- Sentence Transformers
- FAISS or a lightweight vector index
- cosine similarity
- page-aware evidence retrieval

NLI:
Use a Hugging Face NLI model.
Prefer a strong locally runnable model such as:
- microsoft/deberta-v3-base
or another suitable NLI model.

The architecture must allow replacing the NLI model later with a fine-tuned financial NLI model.

ML MODE:
Provide a local/demo fallback if ML dependencies are unavailable.

Do NOT make the UI fail simply because a model is not downloaded.

DATABASE:
Use SQLite for local development.

Store:
- documents
- verification sessions

- evidence
- classification results
